## Problem 3(e): Robust regression and gradient verification

**Expectation and assistance.** Before verification, I expected the gradient of the prescribed *sum* of shifted Huber losses to agree with a sufficiently local directional finite difference. Dividing the loss by the five samples should divide its gradient by five. I used Codex (GPT-6 Astra) to implement the mathematical functions in `src/p3.py` and examine these expectations. The earlier implementation prompt and pre-run expectation should be retained with the original conversation; they are not visible in the four screenshots saved here.

**Evidence brought back to the agent.** I first asked the agent to compare `huber_branches.csv` with the inner and outer formulas and to check whether the code summed the shifted losses ([exchange 1](../results/AI-help-prove/2026-09-29_21-57.png)). It found $h_\mu(0)=\mu/2$, derivatives $(-1,-0.5,0,0.5,1)$ at the five prescribed normalized residuals, and `np.sum` without division by $n$. I then returned values from `gradient_verification.csv`: at $\mu=t=10^{-5}$, the central difference was $0.7624999999999995$ against the analytic directional derivative $1.1$; at $t\approx10^{-6}$, it was $1.0999999999999994$. The mean-loss difference at the smaller step was $0.2200000000000004$, giving a sum-to-mean ratio of about five ([exchange 2](../results/AI-help-prove/2026-09-29_21-57_1.png)). I asked why the larger step differed and how finite-difference error differs from first-order Taylor loss-change error. The agent explained that a step of size $\mu$ reaches other Huber branches, whereas the smaller step measures the local slope more closely.

**Decision.** I retained the implementation: the branch check and small-step difference support the stated gradient, while the factor of five supports sum-versus-mean scaling. The two errors answer different questions: $|[L(\theta+tv)-L(\theta-tv)]/(2t)-\nabla L(\theta)^\top v|$ checks a directional derivative, whereas $|L(\theta+tv)-L(\theta)-t\nabla L(\theta)^\top v|$ checks a finite loss change against its linear approximation. Full values and code are in `results/p3-verify-20260929/` and `src/p3.py`.

## Problem 5(e): Pocket audit and test-error behavior

**Expectation and assistance.** Before verification, I expected pocket *training* error to equal the running minimum of current-perceptron training errors, so it should never increase. I did not expect the same guarantee for test error. I used Codex (GPT-6 Astra) to implement and audit `src/p5.py`. The opening prompt containing this expectation should be kept with the original conversation; it is not shown in the saved screenshots.

**Evidence brought back to the agent.** In the seven-row `toy_trace.csv`, update 1 left pocket error at $0.5$, update 2 lowered it to $0.25$, and update 3 raised current error to $0.5$ while pocket stayed at $0.25$. I asked the agent to recompute update 2 from the four samples and check the strict-improvement rule ([exchange 3](../results/AI-help-prove/2026-09-29_21-57_2.png)). With current weights $(0,-1,0)$, the first three scores are zero and predict $+1$; the fourth score is $-1$ and predicts $-1$. Only the sample with label $-1$ among the first three is wrong, giving $1/4$. I later returned two real pocket test-error rises from `trajectory.csv`: updates 53–54 changed training error from $62/1669$ to $61/1669$ while test error changed from $29/434$ to $30/434$; updates 452–453 changed training error from $56/1669$ to $55/1669$ while test error changed from $26/434$ to $28/434$ ([exchange 4](../results/AI-help-prove/2026-09-29_21-58.png)). The agent checked that both pocket replacements were triggered by strictly lower training error.

**Decision.** I retained the code. The toy pocket sequence $(0.5,0.5,0.25,0.25,0.25,0.25,0.25)$ equals the running minimum of current training error. The full-run audit checks this property across saved states. Pocket selection uses training error only; test scores are calculated from frozen states after training. Consequently, these two test-error increases are compatible with a correct pocket implementation. Full values and code are in `results/p5-baseline-20260929/`, `results/p5-audit-20260929/`, and `src/p5.py`.
